# CWMoney 檔案格式規格

> 狀態：逆向分析中 · 最後更新 2026-09-29
> 範圍：**CWMoney 經典版**（Android `com.lib.cwmoneyex`，匯出檔名前綴 `cwmoney_ex2_db`）
> **本文件的範例都是虛構資料。** 真實樣本含有個人財務資訊和手機載具條碼，**不能放進 repo**。

## 分析過的樣本

| 樣本 | 格式 | 筆數 | 日期範圍 | 備註 |
|---|---|---|---|---|
| `cwmoney_ex2_db_CSV_20181005.csv` | A（HTML） | — | — | 只從 Drive 預覽分析 |
| `cwmoney_ex2_db_CSV_20181208.csv` | A（HTML） | — | — | 只從 Drive 預覽分析，右側有使用者自己加的樞紐分析 |
| `cwmoney_ex2_db_CSV_20260620.csv` | **B（CSV）** | 17,158 | 2016/05/31 – 2026/06/18 | 完整的位元組層級分析 |
| `cwmoney_ex2_db_CSV_20260929.csv` | **B（CSV）** | 128 | 2026/09/01 – 2026/09/29 | 只有 9 月，可見**匯出時可以選日期區間** |

同一個經典版 App 在不同時期匯出的格式**不一樣**，匯入器要能自動判斷：

- **格式 A（舊）**：副檔名 `.csv`，內容其實是 Excel HTML 表格。
- **格式 B（新）**：真正的 CSV，但有幾個不符合標準的地方（見 2.1）。

兩種格式的 **15 個欄位和語意相同**，只有容器、編碼細節和日期格式不同。

---

## 1. 格式判斷

```
讀前 512 bytes
├─ 以 "<!doctype html" 或 "<table" 開頭（不分大小寫） → 格式 A
├─ 以 "\"日期\",\"類別\"" 開頭（Big5 位元組 22 A4 E9 B4 C1 22 2C） → 格式 B
├─ 是 xlsx（開頭 PK\x03\x04） → 使用者用 Excel 另存的檔案，照欄位名稱對應
└─ 以上都不是 → 嘗試 UTF-8 CSV，失敗就回報「無法辨識」
```

## 2. 格式 B：CSV（2026 年的樣本）

### 2.1 容器與編碼

| 項目 | 規格 |
|---|---|
| 編碼 | **Big5-HKSCS**，沒有 BOM。⚠️ 不能用 CP950：真實樣本裡有 HKSCS 擴充字（例如 `0x9DE8`），CP950 會解碼失敗 |
| 分隔符號 | `,` |
| 引號 | **每個欄位都用 `"` 包起來**，包括數字 |
| **記錄分隔** | **CRLF（`\r\n`）**，而且只當作記錄分隔 |
| 欄位內換行 | **只有 LF（`\n`）**，出現在「備註」（發票明細） |
| ⚠️ **引號跳脫** | **沒有跳脫**。欄位內容裡的 `"` 會原樣輸出，例如商品名稱 `13"手套`。標準 CSV parser 碰到這種情況會把後面好幾列讀錯（真實樣本有 1 筆） |
| 標題列 | 第 1 列，15 個欄位 |
| 排序 | 依日期由新到舊 |

**解析演算法**（在 17,158 筆樣本上驗證過，全部正確）：

```
text    = decode(bytes, "big5hkscs")
records = text.split("\r\n")          # 只用 CRLF 切，欄位內的 LF 保留
for line in records[1:]:
    if line == "": continue
    assert line.startswith('"') and line.endswith('"')
    fields = line[1:-1].split('","', maxsplit=14)   # 最多切 14 次，備註是最後一欄，裡面的 " 不影響
    assert len(fields) == 15
```

### 2.2 欄位

| # | 欄位 | 格式（格式 B） | 觀察（17,158 筆） |
|---|---|---|---|
| 1 | **日期** | `YYYY/MM/DD`（**有補零**） | |
| 2 | **類別** | `支出` \| `收入` | 支出 13,996、收入 3,162 |
| 3 | **主分類** | 文字 | 轉帳列是空的。支出有 8 個、收入有 4 個 |
| 4 | **子分類** | 文字 | 共 66 個 |
| 5 | **帳戶** | 文字 | 使用者習慣用 `類型-名稱` 命名，例如 `信用卡-X`、`活存-X`、`美金-X`、`股票-X`，但這**不是 App 的規則**，也有沒有前綴的帳戶名稱 |
| 6 | **專案** | 文字 | 預設是 `無特別專案`（99.2%） |
| 7 | **金額** | 十進位數字字串 | **可以是負數**（47 筆，例如投資虧損記成負的收入）、**可以有小數**（49 筆，外幣） |
| 8 | **匯率** | 十進位數字字串 | 台幣是 `1`；外幣例如 `32.37`、`0.22`、`0.2`。⚠️ **這是四捨五入過的顯示值** |
| 9 | **小計** | 十進位數字字串 | **換算成台幣的金額，以這一欄為準**。有 128 筆 `≠ 金額 × 匯率`（因為匯率被四捨五入；甚至有台幣紀錄差 0.01，是浮點誤差） |
| 10 | **建檔時間** | `YYYY/MM/DD HH:MM:SS`（**有秒數**） | 有 2 筆是空的 |
| 11 | **GPS** | `""`、`"0:0"`、`"0.0 : 0.0"` | 樣本裡**沒有真的座標**。舊的手動紀錄是 `0:0`，發票紀錄是 `0.0 : 0.0` |
| 12 | **地址** | 文字 | 預設是一個**空白字元** `" "`；發票紀錄是 `(賣方名稱,賣方地址)`；少數手動紀錄是使用者輸入的地點 |
| 13 | **發票號碼** | `[A-Z]{2}\d{8}` 或空白 | 3,631 筆 |
| 14 | **轉帳** | `0` \| `1` \| **`2`** | 見 2.3 |
| 15 | **備註** | 文字，可以有多行（LF） | 見 2.4 |

⚠️ **匯入時要同時保留「金額」和「小計」的原始字串**，不能用 `金額 × 匯率` 重新計算小計，否則報表金額會對不上 CWMoney。

### 2.3 轉帳（`轉帳` = 1 或 2）

**`轉帳=1`：轉帳的兩邊。** 一筆轉帳原則上是兩列：

| 列 | 類別 | 帳戶 | 意義 |
|---|---|---|---|
| 第 1 列 | `收入` | 轉入帳戶 | 匯出時一定排在前面（2,231 對都是這樣） |
| 第 2 列 | `支出` | 轉出帳戶 | |

- 兩列的**日期和建檔時間相同**。
- 同幣別時金額相同；**跨幣別時金額不同**（例如美金帳戶轉到台幣帳戶），但「小計」通常相同。
- 備註的預設值是 `[帳戶轉帳]`，使用者也可以自己改（約 30%）。

**配對統計（4,632 列）：**

| 情況 | 數量 | 處理方式 |
|---|---|---|
| `(日期, 建檔時間)` 完全相同，一收一支 | 2,231 對 | 直接配對 |
| 建檔時間差 1–2 秒（真實樣本裡看得到，例如 `10:00:01` 和 `10:00:00`） | 33 對 | 模糊配對：±2 秒內、類別相反、小計相同 |
| **只有單邊**（大多是 2016–2019 年的資料） | **104 列** | 當成「單邊轉帳」匯入，並標記要使用者確認。可能是另一邊被刪掉或修改過；`.idb` 裡應該有真正的關聯 |

**`轉帳=2`：轉帳手續費**（29 筆）
- 只有一列，`類別=支出`，**有分類**（使用者自己選的，例如「手續費」子分類）。
- 備註是 `[手續費][帳戶轉帳]`。
- 有 13 筆能用建檔時間對到它的轉帳，其他的對不到。對應到 Aura 的 `Txn.fee_of`，對不到就當成一般支出。

### 2.4 發票紀錄的備註格式

```
<品名>x<數量>=<金額>\n
<品名>x<數量>=<金額>\n
...
(<賣方統編>,<賣方名稱>)\n
[手機條碼,<載具號碼>]
```

虛構範例：

```
茶葉蛋x2=20
鮮奶x1=45
點數折抵x1=-10
(12345678,某某便利商店股份有限公司XX門市)
[手機條碼,/ABC+123]
```

- 每個品項一行，用**最後一個** `x<數量>=<金額>` 來切。品名本身可能有 `x`、`=`、`"`、`?`。
- **數量可以有小數**（例如加油 `x56.68=1853`）。
- 金額可以是負數（折扣、點數）或 0（贈品、套餐內容）。
- 品項合計**不一定等於**紀錄的金額：使用者可能改過金額、用點數折抵，或只記了部分金額。**以「金額」欄為準**，明細只是參考。
- 有 9 筆發票紀錄沒有 `[手機條碼,…]` 這一行。
- 格式 A（2018）的明細是**擠在同一行**，沒有換行分隔，解析時用 `x\d+(\.\d+)?=-?\d+` 當邊界。

### 2.5 其他語意

- 分類屬於支出還是收入由「類別」決定。支出和收入的主分類名稱可能重複，所以 key 用 `(類別, 主分類, 子分類)`。
- 帳戶類型、帳戶幣別、期初餘額 **CSV 裡都沒有**。帳戶幣別可以從 `匯率≠1` 推斷（樣本裡「美金-」、「日幣-」、美股帳戶都是外幣）。
- 預算、週期性收支、照片、分類圖示和排序、沒用過的分類 **CSV 裡都沒有**。

## 3. 格式 A：Excel HTML（2018 年的樣本）

| 項目 | 規格 |
|---|---|
| 容器 | XHTML 1.0 Transitional，加上 `<!--[if gte mso 9]>` 的 `x:ExcelWorkbook` 區塊，一個 `<table>` |
| 編碼 | Big5（建議一律用 `big5hkscs` 解碼） |
| 日期 | `YYYY/M/D`（**沒有補零**） |
| 建檔時間 | `YYYY/M/D HH:MM`（**沒有秒數**） |
| 發票明細 | 在同一行裡，沒有換行 |
| 欄位 | 跟格式 B 同樣 15 欄。第 16 欄以後如果有內容（例如使用者自己加的樞紐分析），**忽略** |

## 4. 對應到 Aura 的資料模型

| CWMoney | Aura | 規則 |
|---|---|---|
| 日期 | `Txn.date` | 補零或不補零的日期都要能讀 |
| 類別＋轉帳 | `Txn.kind` | 轉帳=0 → `expense`/`income`；轉帳=1 → 配對成 `transfer`；轉帳=2 → `expense`，並設定 `fee_of` |
| 主分類／子分類 | `Category` | key 是 `(kind, 主分類, 子分類)`，依名稱 upsert |
| 帳戶 | `Account` | 依名稱 upsert；`currency` 從匯率推斷；`type` 從名稱前綴推測，之後讓使用者確認 |
| 專案 | `Project` | `無特別專案` → `null` |
| 金額 | `Txn.amount`（decimal） | 保留原始精度，可以是負數 |
| 匯率 | `Txn.fx_rate_display` | 只拿來顯示 |
| 小計 | `Txn.base_amount`（decimal） | **報表以這一欄為準** |
| 建檔時間 | `Txn.created_at` | 可以是空的 |
| GPS | `Txn.lat`/`lng` | `0:0`、`0.0 : 0.0` 和空白都當成 `null` |
| 地址 | `Txn.place` 或 `Invoice.seller_address` | `" "` → `null` |
| 發票號碼＋備註裡的明細 | `Invoice`＋`InvoiceItem[]` | 載具號碼存到 `Invoice.carrier`，**匯出和送給 AI 之前一律遮蔽** |
| 備註 | `Txn.note` | 系統產生的 `[帳戶轉帳]` 不存；發票紀錄的 note 只保留使用者自己加的部分 |
| 整列原始字串 | `Txn.legacy_payload` | 保留原始字串，之後可以原樣匯出 |

## 5. SQLite 備份檔（`.sdb`／`.idb`）— 選用，沒有樣本

已知資訊：兩種都是 SQLite 3；主要的紀錄資料表是 `rec_table`，欄位用 `i_` 當前綴（`i_item`、`i_create`、`i_photo`、`i_invoice`、`i_gps`、`i_rev1`、`i_rev2`）。

**Aura 以 CSV 匯入為主，不需要備份檔。** 備份檔只有在以下情況才有用：
- 補齊 CSV 沒有的資訊：期初餘額、帳戶類型和幣別、預算、週期收支、照片、單邊轉帳的真正對象。
- 產生 CWMoney 能還原的檔案，讓使用者可以搬回去。

在沒有備份檔的情況下，這些資訊由使用者在 Aura 裡補填。期初餘額已經實作：輸入某一天的實際餘額（通常是今天），Aura 會用紀錄推算期初餘額和目前餘額，詳見 `packages/aura_core/lib/src/balance.dart`。
