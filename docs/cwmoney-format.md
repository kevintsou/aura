# CWMoney 檔案格式規格

> 狀態：逆向分析中 · 最後更新 2026-09-29
> 分析樣本：使用者提供的 CWMoney 經典版匯出檔 `cwmoney_ex2_db_CSV_20181208.csv`、`cwmoney_ex2_db_CSV_20181005.csv`（檔名的 `ex2` 對應經典版 `com.lib.cwmoneyex`）。
> **本文件的範例都是虛構資料**，真實樣本含有個人財務資訊和手機載具條碼，不能放進 repo。

## 1. 「CSV」匯出檔（經典版）

### 1.1 檔案容器：其實不是 CSV

| 項目 | 實際情況 |
|---|---|
| 副檔名 | `.csv` |
| 檔名規則 | `cwmoney_ex2_db_CSV_YYYYMMDD.csv`（日期是匯出日） |
| **實際格式** | **HTML 表格**（XHTML 1.0 Transitional doctype），加上 `<!--[if gte mso 9]>` 的 Excel XML 區塊（`x:ExcelWorkbook`、`Sheet1`）。也就是 Excel 的「HTML 試算表」格式，Excel 會把它當成活頁簿打開 |
| **文字編碼** | **Big5 / CP950**（不是 UTF-8）。欄位名稱和內容都用 CP950 反向驗證過 |
| 結構 | 一個 `<table>`：第 1 列是標題，之後每列一筆紀錄 |
| 排序 | 依「日期」由新到舊 |

**匯入時要注意：**
- **不能用 CSV parser 讀**，要先偵測內容開頭是不是 `<!doctype html` 或 `<table`，再用 HTML parser 讀 `<tr>` 和 `<td>`。
- 編碼偵測的順序是：有 UTF-8 BOM 就用 UTF-8；有 `<meta charset>` 就照它；**否則預設 CP950**，解碼失敗再退回 UTF-8。
- 使用者可能用 Excel 開過這個檔案，又另存成 `.xlsx`（使用者的 Drive 裡也有 `cwmoney_ex2_db_CSV_*.xlsx`），所以匯入器也要支援 xlsx，欄位對應相同。
- 使用者可能在檔案右側加了自己的欄位。例如樣本 `20181208` 的第 19–20 欄是 Excel 樞紐分析表（「加總 - 金額」、「總計」），而且這個檔案在建立後約一小時被修改過。**只讀前 15 個有名稱的欄位，其他欄位忽略。**

### 1.2 欄位定義（共 15 欄）

| # | 欄位名稱 | 型別／格式 | 說明與觀察 |
|---|---|---|---|
| 1 | **日期** | `YYYY/M/D`（月、日**不補零**） | 交易日期，可以晚於建檔時間（預先記帳） |
| 2 | **類別** | `支出` \| `收入` | 只有這兩種值。**轉帳不是獨立的類別**，見 1.3 |
| 3 | **主分類** | 文字 | 例如「生活費」、「行車交通」。轉帳時是空的 |
| 4 | **子分類** | 文字 | 例如「早餐」、「加油」。轉帳時是空的 |
| 5 | **帳戶** | 文字 | 帳戶名稱，例如「現金」、「信用卡-XX」、「銀行-XX」。CSV 裡**沒有帳戶類型**，只能從名稱猜 |
| 6 | **專案** | 文字 | 預設值是 **`無特別專案`**（等同沒有專案）。名稱可能含括號和數字，例如 `裝修(001/202403)` |
| 7 | **金額** | 數字 | 原幣金額，可以是 `0`（例如點數全額折抵） |
| 8 | **匯率** | 數字 | 本國幣帳戶是 `1` |
| 9 | **小計** | 數字 | 等於 `金額 × 匯率`，是換算成本國幣的金額 |
| 10 | **建檔時間** | `YYYY/M/D HH:MM`（24 小時制，沒有秒） | 紀錄的建立或修改時間，不是交易時間 |
| 11 | **GPS** | `緯度 : 經度`，例如 `0.0 : 0.0`；或空白 | 發票匯入的紀錄是 `0.0 : 0.0`，大多數手動紀錄是空白 |
| 12 | **地址** | 文字 | 發票紀錄的格式是 `(賣方名稱,賣方地址)`，手動紀錄通常是一個空白字元 |
| 13 | **發票號碼** | `AA12345678`（2 碼英文加 8 碼數字）或空白 | |
| 14 | **轉帳** | `0` \| `1` | `1` 表示這一列是轉帳的其中一邊 |
| 15 | **備註** | 文字 | 使用者輸入。發票紀錄會自動產生明細，見 1.4 |

### 1.3 轉帳的表示方式

一筆轉帳會拆成**兩列**，兩列的日期、建檔時間、金額都相同，而且都是 `轉帳=1`：

| 日期 | 類別 | 主分類 | 子分類 | 帳戶 | 金額 | 轉帳 | 備註 |
|---|---|---|---|---|---|---|---|
| 2024/3/5 | 收入 | | | 現金 | 3000 | 1 | [帳戶轉帳] |
| 2024/3/5 | 支出 | | | 銀行-A | 3000 | 1 | [帳戶轉帳] |

- `支出` 那一列是**轉出帳戶**，`收入` 那一列是**轉入帳戶**。
- 備註固定是 `[帳戶轉帳]`（系統產生）。
- 匯出時 `收入` 列排在 `支出` 列之前。
- 繳信用卡帳單也是一般轉帳（從銀行帳戶轉到信用卡帳戶）。

**配對演算法（匯入時）：** 把 `轉帳=1` 的列用 `(日期, 建檔時間, 金額)` 分組，每組配成一對「支出 → 收入」。如果同一組有超過兩列（同一分鐘內有好幾筆同金額的轉帳），就照出現順序兩兩配對，並記一筆 warning。配不起來的列當成單邊調整，匯入完成後提示使用者。

### 1.4 發票自動匯入的紀錄

透過手機條碼載具匯入的發票紀錄有以下特徵：

- `GPS` = `0.0 : 0.0`
- `地址` = `(賣方名稱,賣方地址)`
- `發票號碼` 有值
- `備註` 的格式如下：

```
<品名>x<數量>=<小計><品名>x<數量>=<小計>...(<賣方統編>,<賣方名稱>)[手機條碼,<載具號碼>]
```

虛構範例：`茶葉蛋x2=20鮮奶x1=45(12345678,某某便利商店股份有限公司XX門市)[手機條碼,/ABC+123]`

- 品項之間**沒有分隔符號**，要用 `x<數量>=<小計>` 當作邊界來切。
- 折扣是負數的品項，例如 `點數折抵x1=-10`。
- 這個格式可以拆成結構化的 `Invoice.items`，**但裡面有使用者的載具號碼，屬於敏感資訊**，要去識別化才能放進測試資料。

### 1.5 CSV 沒有的資訊（所以它不是完整備份）

| 缺少的資訊 | 影響 |
|---|---|
| 帳戶類型、幣別、**期初餘額** | 匯入後的**帳戶餘額會對不上**，要請使用者補填，或從 `.sdb`／`.idb` 讀 |
| 沒用過的分類和專案、分類排序、圖示 | 分類清單不完整 |
| 預算、週期性收支設定 | 完全遺失 |
| 照片 | 完全遺失 |
| 紀錄的內部 ID | 無法做到跟原檔一模一樣的 round-trip |
| 秒數、時區 | 建檔時間只到「分」 |

**結論：** CSV 匯入可以當作「快速搬家」的最低保證，但要**完全相容**，還是需要解析 SQLite 備份檔（`.sdb`／`.idb`）。這跟官方「CSV 只能匯出、不能還原」的說法一致。

### 1.6 Aura 對應（CSV → Aura model）

| CWMoney 欄位 | Aura 欄位 |
|---|---|
| 日期 | `Txn.date` |
| 類別＋轉帳 | `Txn.kind`（`expense` \| `income` \| `transfer`） |
| 主分類／子分類 | `Category`（parent／child，依名稱 upsert；分類屬於支出還是收入由「類別」決定） |
| 帳戶 | `Account`（依名稱 upsert，`type` 從名稱推測，例如含「信用卡」就是 `credit`，「現金」就是 `cash`，其他預設 `bank`，之後讓使用者確認） |
| 專案 | `Project`；`無特別專案` 對應到 `null` |
| 金額 | `Txn.amount_minor`（台幣以元為單位，外幣照幣別的小數位數轉換） |
| 匯率 | `Txn.fx_rate` |
| 小計 | 只拿來驗證 `金額 × 匯率`，不另外存 |
| 建檔時間 | `Txn.created_at` |
| GPS | `Txn.lat`／`lng`（`0.0 : 0.0` 視為沒有位置） |
| 地址、發票號碼、發票明細 | `Invoice`（number、seller、items），並設定 `txn_id` |
| 備註 | `Txn.note`（系統產生的 `[帳戶轉帳]` 不存） |
| 整列原始值 | `Txn.legacy_payload`（保留原始字串，之後可以原樣匯出） |

### 1.7 Aura 匯出（相容 CWMoney 的格式）

要讓 CWMoney 使用者的 Excel 分析流程可以繼續用，匯出時要：
- 產生**同樣結構的 HTML 表格**、使用 CP950 編碼、副檔名 `.csv`，而且欄位順序和名稱都要相同。
- 同時提供「標準 UTF-8 CSV」的選項（這才是真正的 CSV，給其他工具用）。

## 2. SQLite 備份檔（`.sdb`／`.idb`）

**尚未取得樣本。** 目前已知的只有：
- 兩種都是 SQLite 3 格式；Android 舊版用 `.sdb`，iOS 和 Android 新版用 `.idb`。
- 主要的紀錄資料表是 `rec_table`，欄位用 `i_` 當前綴（已知有 `i_item`、`i_create`、`i_photo`、`i_invoice`、`i_gps`、`i_rev1`、`i_rev2`）。

從 CSV 的欄位推測，`rec_table` 應該至少有：日期、收支類型、分類 ID、子分類 ID、帳戶 ID、專案 ID、金額、匯率、建檔時間、GPS、地址、發票號碼、轉帳旗標（或對應的轉帳 ID）、備註、照片。

**下一步：** 需要一份經典版的 `.sdb` 或 `.idb` 備份，最好跟上面的 CSV 是**同一個時間點**的，這樣可以逐欄比對。
